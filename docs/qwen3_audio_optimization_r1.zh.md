# Qwen3 ASR / TTS：参考 RhinoVLA 的 R1 推理优化

2026-10-09，在 `feat/qwen3-audio-rpu` 分支完成。基线模型实现为 `7fd9eb4`，基线评测提交为 `554fe61`；沿用[首次评测](qwen3_audio_benchmark_r1.zh.md)的 R1、checkpoint、Launch、算子资产、线程数和输入，不改变权重、不减少模型层数、不缩短生成上限。

**ASR 固定输入提速 16.38 倍，20 条转写和 token 均未改变；TTS 固定输入耗时减少 26.75%，10 条波形逐点一致。** ASR 在所测短音频上的离线处理已快于播放速度；TTS 仍慢于播放速度。

## 对照 RhinoVLA 后的改动

| RhinoVLA 的处理方式 | 语音模型中的应用 |
|---|---|
| 在设备分配前选择公共 caching allocator | 两个语音加载器使用相同分配器，减少反复分配/释放；不修改 CPU/RPU 必需的同步 |
| 持有 KV 存储，通过 `reset_to_position(0)` 开始下一条序列 | ASR 不再每次申请并清零 28 层 KV；TTS Talker/Predictor 保留各自 KV，尤其避免每个声学 token 都重新申请 Predictor KV |
| 区分稳定部分和每次变化的输入，只复用有完整语义键的结果 | TTS 仅缓存最近一次说话人 embedding，以解码后的音频内容 SHA256 为键；每次仍读取、检查文件，内容变更即重新计算 |
| 只计算后续流程需要的内容，减少 CPU/RPU 搬运 | ASR 只取最后一个 hidden position 回 CPU 计算输出头；TTS 的 speaker-only 模式不计算随后会被丢弃的参考 codec token |

参考源码：[RhinoVLA 分配器与 KV/前缀流程](../python/rpu_backend/adapters/rhinovla/pipeline.py)、[RhinoVLA 复用输入/输出存储](../python/rpu_backend/adapters/rhinovla/vision.py)、[公共 KV reset](../python/rpu_backend/api/cache.py)。没有照搬 RhinoVLA 专用的动作循环、量化或 fast-replay 开关；普通语音 decode 不满足其 prefill 快速路径的条件。

ASR 另有一个更大的已测瓶颈：R1 的 CPU FP16 卷积很慢。固定输入诊断中三层卷积分别约 0.045、6.638、1.620 秒；用原先 FP16-rounded 权重提升至 FP32 计算后，约 0.042、0.056、0.024 秒。每层结果立即舍入回 FP16，音频 encoder 的 111 个 Linear 和 28 层文本 decoder 仍在 RPU。这里改变了 CPU 卷积算术精度，不能描述为原 FP16 路径逐位相等。TTS 的 Talker、Predictor 和 16 个输出头仍在 RPU，speaker/codec 保持 CPU FP32。

同输入卷积输出的诊断 MSE 分别为 `1.50e-13`、`2.78e-10`、`2.00e-10`，max-abs 分别为 `0.000488`、`0.003906`、`0.001953`；仅记录差异，不设任意数值阈值。该诊断样本的单位置输出头与原全前缀输出头末位置 MSE 为 0、top-1 相同。性能结论使用下方关闭 profiler 的正式测试，未用 profiler 耗时计算加速比。

## 同协议速度对比

使用原评测脚本：CPU 线程数 4、batch 1、greedy、最多 64 token；每模型完整预热 2 次，随后固定输入测量 5 次，再运行原 ASR 20 条 / TTS 10 条不同输入。保持完整 API 计时边界，ASR WAV 解码在计时外、特征提取在内；TTS 参考音频读取/校验/内容哈希和生成波形均在计时内。共享参考音频时命中说话人缓存，首次或内容变化时会重新提取 embedding。

ASR 固定录音 4.204 秒；TTS 固定文本“你好，欢迎使用语音助手。”，生成音频 2.48 秒。RTF 为总耗时/总音频时长，低于 1 表示离线处理快于播放；它不是流式首包延迟。

| 指标 | ASR 优化前 | ASR 优化后 | TTS 优化前 | TTS 优化后 |
|---|---:|---:|---:|---:|
| 耗时中位数 | 10.465 秒 | **0.639 秒** | 5.237 秒 | **3.836 秒** |
| 耗时均值 | 10.491 秒 | 0.639 秒 | 5.258 秒 | 3.846 秒 |
| 最小–最大 | 10.453–10.598 秒 | 0.630–0.651 秒 | 5.213–5.359 秒 | 3.822–3.877 秒 |
| RTF | 2.496 | **0.152** | 2.120 | **1.551** |
| 每秒墙钟处理/生成音频 | 0.401 秒 | 6.579 秒 | 0.472 秒 | 0.645 秒 |
| 中位耗时加速比 | — | **16.38 倍** | — | **1.37 倍** |
| 中位耗时下降 | — | **93.89%** | — | **26.75%** |
| 加载，不含包导入 | 23.454 秒 | 23.212 秒 | 32.299 秒 | 32.082 秒 |

加载未清空 OS 文件缓存，不将小幅加载差异解释为优化收益。ASR 预热耗时 1.101、0.645 秒；TTS 为 4.317、3.917 秒。正式计时期间模型进程串行运行并持有既有设备锁，无 profiler。

|---|---:|---:|---:|---:|---:|
| ASR 中文 | 10 | 10.600 秒 | 1.181 秒 | 1.952 | 0.218 |
| ASR 英文 | 10 | 10.598 秒 | 1.357 秒 | 2.177 | 0.279 |

ASR 不同长度会重新构建 Graph，故其多输入耗时高于固定输入重复运行。TTS 剩余开销仍包含逐步生成和 CPU codec，不能将本次优化描述为达到实时。

## 识别质量与输出检查

评分和样本严格沿用首次评测，不重新筛选样本或修改归一化。中文为 AISHELL 固定子集 10 条、7 位说话人、165 字；英文为 LibriSpeech dummy 固定子集 10 条、仅 1 位说话人、124 词。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 中文 CER | 1.82% | **1.82%** |
| 中文字正确率（1−CER） | 98.18% | **98.18%** |
| 中文整句一致率 | 9/10 | **9/10** |
| 英文 WER | 5.65% | **5.65%** |
| 英文词正确率（1−WER） | 94.35% | **94.35%** |
| 英文整句一致率 | 4/10 | **4/10** |

20 条 ASR 的完整生成 token 序列与优化前全部相同，无样本触及 64-token 上限。TTS 10 条返回波形与原文件逐点一致，因此直接复用原官方 CPU FP32 ASR 转写证据：中文 5 句 CER=0%、英文 5 句 WER=0%，没有重复运行相同波形的评分器。TTS 仍有中文 1 条、英文 2 条达到上限，其文本完整，但不能保证更长句自然结束。

## 缓存与回归验证

- 受影响的主机测试 61 项通过，覆盖准入、输出所有权、失败清理、ASR 中断后的 KV 位置重置、TTS Predictor 不同输入/长度复用、参考音频原路径内容变更。
- ASR 固定输入 Graph size=2，测量阶段 REPLAY 31→42→53→64→75；每次 111 个音频 Linear 均执行 RPU。
- TTS Talker/Predictor 各一个 Graph，REPLAY 分别为 146→342、1487→3471；16 个输出头每次均执行 RPU。全部 Graph invariant 为 true，固定输入重复输出一致。
- ASR 同长度换内容、0.5/8 秒边界、切回原输入及关闭重载通过，token 与既有基线一致；TTS 更换参考音频、切回原参考、保留旧输出及关闭重载通过，切回/重载波形逐点一致。详见机器可读证据。
